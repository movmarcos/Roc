# Editorial and technical verification standard

1. A course promise must map to a demonstrated learning outcome.
2. Distinguish observed behaviour, official vendor documentation, hypothesis and recommendation.
3. Time-sensitive product behaviour needs official references and a **last-verified date**.
4. Terminal commands must be executed in an isolated test environment before publication.
5. Labs must show prerequisites, expected outputs, verification, cleanup and safety.
6. Record source attribution and license compatibility for external content.
7. Do not publish private project code, credentials, user data, or private prompts.
8. Keep a human review gate for security, technical claims, accessibility and commercial rights.
